PHASE 12023

Prompt (프롬프트 · 지시문)

ChatGPT, Claude, Gemini

  • 자연어로 의도와 제약을 전달
  • 역할·형식·예시로 답변 품질 조정
  • 모델의 추론을 끌어내기 위함
PHASE 22025

Context (컨텍스트 · 맥락)

Cursor, Manus

  • 코드베이스·문서·브라우저 상태를 맥락으로 연결
  • 필요한 파일·외부 정보를 찾아 배경 구성
  • 긴 작업에서 맥락 손실을 줄이기 위함
PHASE 32026

Harness (하네스 · 운영틀)

Claude Code, Codex

  • 파일 수정·명령 실행·테스트를 한 루프로 연결
  • 작업을 나누고 실행 결과를 보며 다음 액션 결정
  • 결과를 검증하고 반복 개선하기 위함
요리 비유 — 프롬프트는 "스파게티 만들어줘" 한마디. 컨텍스트는 "냉장고에 토마토와 면이 있어, 4인분, 매운 거 좋아함"까지 알려주기. 하네스는 아예 로봇 셰프가 냉장고를 열고 재료 꺼내 끓이고 간 보고 다시 끓이며 완성까지 책임지는 것.

LLM
Safety & Scale (안전·확장 · 가장 바깥)

Verification (검증) · Guardrails (안전장치) · Tool Scoping (도구 범위) · Subagent Orchestration (서브에이전트 조율)

Capabilities (능력 · 중간)

Tools (도구) · Memory (기억) · Context (맥락) · State (상태)

Runtime (실행부 · 안쪽)

회사 비유 — LLM은 신입사원의 두뇌, Runtime은 그가 쓰는 책상·노트북, Capabilities는 사내 시스템 접근 권한과 회사 메모리(위키·캘린더), Safety & Scale은 컴플라이언스 부서와 결재선 — 바깥으로 갈수록 "안전하게 일을 잘 굴리기 위한 장치"가 늘어납니다.

Agent (에이전트) · Skill (스킬) · Harness (하네스) 는 모두 다릅니다

셋의 역할을 분리해서 기억하세요

1. Agent

두뇌

목표를 해석하고 다음 행동을 결정하는 모델 중심의 판단 주체

  • 목표·제약 해석
  • 계획 수립과 우선순위 결정
  • 결과를 보고 전략 조정

2. Skills

손과 발

Agent가 필요할 때 호출하는 재사용 가능한 작업 절차와 실행 능력

  • 검색·파일 처리·API 연동
  • 스크립트·템플릿·지침 묶음
  • 반복 작업을 일관되게 수행

3. Harness

신경계

Agent가 안전하게 일하도록 컨텍스트·권한·상태·실행 루프를 조율하는 운영 환경

  • 허용 도구와 안전 경계 관리
  • 호출 순서와 재시도 제어
  • 대화·메모리·상태 추적
요리사 비유 — Agent는 요리사(판단·결정), Skill은 그가 가진 레시피와 칼질 기술(재사용 능력), Harness는 그가 일하는 주방 전체(가스레인지·환기·소화기·동선). 좋은 주방이 없으면 아무리 요리사가 뛰어나도 큰 식당은 굴리기 어렵습니다.

왜 사내에서 하네스가 필요한가

개인이 ChatGPT 한 번 묻고 답 받는 것과, 회사 업무가 끝까지 굴러가는 것은 다른 문제입니다.

업무가 많고 복잡합니다

  • 분석·문서 작성·검수·공유까지 한 번에
  • 여러 단계를 빠짐없이 순서대로
  • 매번 손으로 하면 시간이 부족

품질·일관성이 중요합니다

  • 사내 톤·형식·용어가 통일되어야
  • "임원이 30초에 읽도록" 같은 규칙
  • 실수 1건이 큰 비용이 되는 영역 다수

보안·승인 경계가 분명합니다

  • 원본 데이터는 절대 수정 금지
  • 외부 전송은 사람이 한 번 더 검토
  • 도구·권한을 사전에 좁혀야

하네스로 만들 만한 사내 후보: 주간/월간 보고서, 회의록 정리, 이메일 초안, 경쟁사 리서치, 데이터 검증, 문서 검수 — 부서 불문하고 매주 반복되는 작업 전부.

인턴 vs 정직원 비유 — 인턴에게 "보고서 좀 써줘"(단발 프롬프트) 하면 매번 다시 설명해야 함. 정직원에겐 업무 매뉴얼·결재선·시스템 권한(= 하네스)이 있어서 알아서 끝까지 굴러갑니다. 회사가 직원에게 "하네스"를 제공하듯, AI에게도 똑같이 필요합니다.

왜 Claude Code는 터미널을 쓰나요?

  • AI에게 "내 컴퓨터의 파일을 읽고 고쳐줘"라고 시키려면 파일 시스템 접근 권한이 필요합니다.

Plan mode — 안전벨트입니다

계획만 보여주고 실행은 안 함. 검토 후 승인하면 그제서야 실행.

❌ Plan mode 없이

"이 코드 리팩터링 해줘" → 클로드가 바로 30개 파일을 수정 → 망함

✅ Plan mode로

"이 코드 리팩터링 해줘" → 클로드가 "이 파일들을 이렇게 바꾸려고 합니다" 계획 출력 → 검토 → 승인하면 실행

전환 방법

키보드: Shift + Tab 을 누르면 모드 (작동 방식) 가 순환됩니다.

  • default(기본) — 매 도구 호출마다 묻기
  • plan(계획만) — 계획만 출력, 실행 X
  • acceptEdits(편집 자동 승인) — 파일 편집은 묻지 않고 진행

권장 사용 패턴

  1. 큰 작업 시작 → plan (계획 먼저)
  2. 계획 검토 후 → default 또는 acceptEdits
  3. 위험한 작업 (파일 삭제·이메일 전송 등) 직전엔 다시 plan
안전벨트 비유 — Plan mode는 차를 출발하기 전 안전벨트와 같습니다. 매번 매면 귀찮지만, 사고가 났을 때 후회하지 않게 해줍니다. 큰 작업·민감한 폴더 수정 전에는 무조건 plan으로 한 번 보고 가는 습관을 들이세요.

"Yes / Yes, and don't ask again / No" 중 선택

  • Read — 파일/디렉토리 읽기

읽기만 하는 작업은 안전하다고 본다

사전 허용 — .claude/settings.json

json · .claude/settings.json 
{
  "permissions": {
    "allow": [
      "Read",
      "Glob",
      "Grep",
      "Edit(reports/*.md)",
      "Write(reports/*.md)"
    ],
    "deny": [
      "Edit(data/*)",
      "Write(data/*)",
      "Bash(rm:*)",
      "Bash(curl:*)"
    ]
  }
}

allow: reports/ 안에서는 자유롭게 작업 가능 · deny: 원본 data/ 폴더는 절대 수정 금지 + 위험한 셸 명령 차단. :* 는 와일드카드 (모두).

잠깐 — .md 가 뭔가요?

마크다운(Markdown)의 약자. 메모장으로도 열리는 그냥 텍스트 파일입니다.

왜 쓰나요?

  • 일반 텍스트인데 제목·목록·강조·코드를 간단한 기호로 표시할 수 있음
  • Notion, GitHub, Slack 모두 자동으로 예쁘게 렌더링
  • AI가 가장 좋아하는 형식 — 구조가 분명해서 잘 이해함
  • 파일 확장자는 .md

어디서 만들고 열까요?

  • 맥: 텍스트 편집기, VS Code, Typora 등
  • 윈도우: 메모장, VS Code, Typora 등
  • 가장 쉬운 방법: Claude Code에게 "CLAUDE.md 파일을 만들어줘"라고 말하면 끝

  • 병렬화 — 여러 서브에이전트를 동시에 돌릴 수 있음
  • 재사용 — 한번 만들면 프로젝트·팀에서 계속 호출

업무에서 흔히 만드는 예

  • doc-reviewer — 문서를 검수해 톤·맞춤법·일관성 체크
  • data-validator — CSV·엑셀의 이상치·중복·누락 확인
  • meeting-summarizer — 회의록 → 결정사항·액션 추출
  • researcher — 웹·사내 위키 검색만 전담
  • translator-ko-en — 한↔영 번역 전문 (사내 톤 반영)

위치

경로범위

예시 — /주간보고 명령 만들기

markdown · .claude/commands/주간보고.md 
---
description: data/ 의 이번 주 CSV 분석 → 임원 보고용 .md 생성
argument-hint: "[특별 강조 사항 (선택)]"
allowed-tools: Read, Glob, Write, Edit
---

다음 절차를 따르세요:

1. `data/` 폴더에서 가장 최근의 CSV 파일을 찾아 읽기
2. 매출 상위 3개 / 하락 1개 / 재고 부족 항목을 식별
3. CLAUDE.md 의 톤·형식 규칙을 따라 마크다운 보고서 작성
4. 산출물: `reports/weekly-YYYY-MM-DD.md` (오늘 날짜)
5. 사용자가 강조해달라고 한 사항: $ARGUMENTS

주의: 원본 CSV 절대 수정 금지. reports/ 폴더에만 새 파일 생성.

사용 예: /주간보고 또는 /주간보고 신제품 출시 직후라 광고비 ROAS 강조

키보드 단축키 비유 — Excel에서 Ctrl+Shift+L 누르면 필터가 한 번에 적용되듯, /주간보고 한 줄이 "데이터 읽기 → 분석 → 보고서 작성"이라는 5단계를 매번 동일하게 실행합니다. 같은 작업을 매주 3번 이상 한다면 이미 슬래시 명령으로 만들 후보.

Hooks — 자동 검증·알림의 빌트인

Claude의 행동 전/후에 내가 정한 셸 명령이 자동 실행됩니다

PreToolUse
(도구 사용 전)

도구 실행 직전. exit 2 (종료 코드 2) 면 차단.

→ "원본 data/ 폴더 수정 시도 막기"

PostToolUse
(도구 사용 후)

도구 실행 직후. 결과 후처리.

→ "보고서 작성 후 자동으로 슬랙에 링크 전송"

Stop / Notification
(종료 / 알림)

세션 종료·알림·프롬프트 제출 시점

→ "긴 작업 끝나면 데스크탑 알림"

중요: 훅 명령은 자동 실행됩니다. 당신이 입력해 둔 명령이 그대로 셸에서 실행되니, 신뢰할 수 있는 명령만 등록하세요.
현관 도어락 비유 — 도어락은 사람이 문을 열려고 할 때마다(이벤트) 자동으로 작동합니다. PreToolUse는 문을 열기 전 비밀번호 확인, PostToolUse는 문이 닫힌 후 자동 잠금. 매번 신경 안 써도 보안과 자동화가 같이 굴러갑니다.
1PreToolUse도구가 실행되기 "직전" 시점 (위험한 명령 차단 용도) 2프롬프트AI에게 하는 한 마디 질문이나 지시문 3셸터미널 안에서 명령을 받아 처리하는 프로그램 (zsh·bash·PowerShell 등)

Hooks 설정 — JSON 구조

설정 파일: .claude/settings.json (팀 공유) 또는 ~/.claude/settings.json (개인)

json · .claude/settings.json (업무 친화 예시) 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | grep -q '^data/' && { echo '원본 데이터 폴더는 수정 금지'; exit 2; } || exit 0"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs -I {} echo \"[$(date '+%H:%M:%S')] 생성: {}\" >> ~/.claude/activity.log"
          }
        ]
      }
    ]
  }
}

동작 원리

  • matcher — 도구 이름 정규식(패턴). 예: "Edit|Write", "Bash", "mcp__github__*"
  • 훅 명령은 표준 입력(stdin)으로 JSON을 받음: {"tool_name": "...", "tool_input": {...}}
  • 종료 코드 2 (exit code 2) = 차단 (PreToolUse 한정). 그 외는 통과.
  • 화면 출력(stdout/stderr)은 사용자에게 그대로 표시됨

⚠️ jq (JSON 처리 도구) 가 없으면 — Mac: brew install jq, Windows: winget install jqlang.jq · 다음 슬라이드는 더 쉬운 알림 예제.

1JSON컴퓨터가 읽기 쉬운 데이터 표기법 ({ "키": "값" } 형식) 2PreToolUse도구가 실행되기 "직전" 시점 (위험한 명령 차단 용도) 3Bash셸 명령을 실행하는 Claude의 도구 4Edit파일을 수정하는 Claude의 도구

shell · 터미널 (claude 밖에서)

업무에서 가장 유용한 3가지 예시

1. Filesystem (내 컴퓨터 특정 폴더 안전 접근) — 사내 보고서 폴더를 통째로 클로드가 읽도록

shell 
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/Documents/reports

2. Slack (채널 검색·메시지 조회) — "이번 주 #marketing 채널 주요 논의 정리해줘"

shell 
claude mcp add slack --env SLACK_BOT_TOKEN=<xoxb-...> \
  -- npx -y @modelcontextprotocol/server-slack

3. Notion (사내 위키 검색) — "지난 분기 OKR 문서 찾아서 요약해줘"

shell 
claude mcp add notion --env NOTION_TOKEN=<secret_...> \
  -- npx -y @notionhq/notion-mcp-server

⚠️ 토큰은 환경 변수로 — settings.json 에 직접 적으면 git 커밋 시 유출 위험. --env 옵션 사용.

  • 경쟁 가설로 디버깅 — 5명이 각자 다른 원인 가설을 동시에 검증, 서로 반박
  • 여러 모듈 동시 개발 — 프론트·백·테스트를 한 명씩 맡아 충돌 없이

TF팀 vs 비서 비유 — Subagent는 비서(시킨 일을 하고 결과만 보고). Agent Teams는 TF팀(여러 명이 서로 의견을 나누고 토론한 뒤 결론을 가져옴). 중요한 의사결정엔 TF가 낫고, 단순 처리엔 비서가 빠르고 쌉니다.

에이전트 사용 시 반드시 피해야 할 패턴

모호한 지시는 작은 오류를 반복시키고 품질 부채를 키웁니다

1

모호한 지시 줄이기

"잘해줘"·"깔끔하게" 같은 추상적 지시는 매번 다른 결과를 만듭니다. CLAUDE.md에 형식·톤·길이·금기 규칙을 구체적으로 명시.

2

불확실할 때 추측하지 못하게

데이터·근거가 부족하면 추정값을 단정형으로 쓰지 말고 사실대로 말하도록. "모르면 모른다고 답하라" 규칙을 명시.

3

검증 없는 종료 막기

결과가 만족스러워 보여도 자동으로 검수 단계를 거치게. PostToolUse 훅이나 doc-reviewer 같은 서브에이전트로 강제.

4

권한·범위 경계 명확히

수정 가능 폴더·금지 도구·승인이 필요한 지점을 사전에 정하기. allowed-tools, settings.json 의 deny 활용.

신입 교육 비유 — 신입에게 "알아서 잘해봐"라고만 하면 매번 다른 결과가 나옵니다. 형식·기준·금기를 명문화하고, 중간 점검하고, 권한 범위를 정해주는 게 교육의 핵심 — Claude도 똑같습니다.
